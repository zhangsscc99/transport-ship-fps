## 客观事实（2026-11-19 实测）

```
文件       index.html 1,423,569 字节（sha256 f34e6deb…）
结构       <style> 内联 CSS（约 20KB）+ 单个内联 <script>（约 1,359 KB）
依赖       外部只有 Google Fonts 三个字族（Big Shoulders Display / IBM Plex Mono / Barlow Condensed）
           three.js 被压缩后整体内联在同一个 script 里
资源       无任何图片、模型、音频文件
```

程序化程度（按关键词出现次数，粗略反映实现重心）：

```
texture     1,165 次     贴图全由代码生成（canvas / 噪声 / 着色器）
shader        244 次     自定义着色器（水面、雨、火光、雾）
AudioContext    3 次     音效由 WebAudio 合成
reload/weapon  75/32 次  完整的枪械状态机
```

## 它证明了什么（对我们的意义）

1. **1.4 MB 能装下一个有观感的 3D FPS**，因为 three.js 压缩后约 600–700 KB，剩下 600–700 KB 是游戏代码。
   → 我们的体积预算：three.js（~650KB）+ 游戏（目标 ≤ 500KB）+ 程序化资源（0）= **gzip 后 < 1.2 MB** 可达。
2. **所有美术都能用代码生成**：几何用 primitive 组合、表面用 canvas 噪声 + 渐变、
   环境氛围靠着色器（雾/雨/水面反射），不需要美术管线。
3. **单文件不是目的，是结果**：把 CSS、库、代码内联进一个 html，可直接双击运行。
   我们采用「源码模块化 + 构建期内联」的方式，不牺牲可维护性。

## 我们照搬的（方法）
- 单页 + 单 bundle 的产物形态（构建期把 JS/CSS 内联进 index.html）
- 贴图用离屏 canvas 程序化绘制（金属划痕 = 噪声 + 高频细节层；锈迹 = 多尺度噪声 + 色调映射）
- 音效用 WebAudio 合成（枪声 = 噪声 burst + 低通扫频 + 短混响；脚步声 = 滤波噪声包络）
- 光照克制：一盏方向光 + 环境光，只有主光投影，靠贴图与雾营造体积感

## 我们不做/不用的
- 它的关卡布局、任务设计、敌人类型（我们做运输船 + 团队竞技）
- 它的任何代码片段、字符串、UI 文案、调色板数值
- 它的 Google Fonts 依赖（我们本地打包字体或用系统字体栈，避免外链）

## 对我们的风险提示
- 参考项目用了 8 小时、445M 输入 token 才成型；我们按每小时 ~10M 免费额度推进，
  必须分 15–25 轮迭代，不能指望一轮出成品。
- 手机端比桌面更需要克制：不做后处理、不做实时阴影级联、draw call 控制在 120 以内。
